1. Quickstart: Build a Plugin in 5 Minutes

Let's build a working telemetry plugin from scratch starting with an empty folder.

1

Open your plugins directory

In Iris on your PC, go to Settings → General → Open Plugins (or open %USERPROFILE%\Documents\Iris\plugins\ in File Explorer).

2

Create your plugin folder

Create a new folder named flight_tracker with two files:

Documents/Iris/plugins/
└── flight_tracker/
    ├── plugin.json
    └── plugin.py
3

Write the manifest (plugin.json)

{
  "name": "flight_tracker",
  "display_name": "Flight Tracker",
  "version": "1.0.0",
  "author": "Your Name",
  "description": "Exposes aircraft telemetry to Iris button decks and gauges.",
  "type": "service",
  "capabilities": {
    "status": true,
    "live_data": true
  },
  "live_data": {
    "fields": [
      {
        "key": "altitude",
        "label": "Altitude",
        "type": "number",
        "unit": "ft",
        "icon": "airplane-takeoff"
      },
      {
        "key": "airspeed",
        "label": "Airspeed",
        "type": "number",
        "unit": "kts",
        "icon": "speedometer"
      }
    ]
  }
}
4

Write the Python logic (plugin.py)

from iris_plugin import BasePlugin

class Plugin(BasePlugin):
    name = "flight_tracker"

    def __init__(self, cfg=None, *args, **kwargs):
        super().__init__(cfg, *args, **kwargs)
        self.altitude = 5000.0
        self.airspeed = 140.0

    def start(self):
        print("[flight_tracker] Plugin started")

    def stop(self):
        print("[flight_tracker] Plugin stopped")

    def poll(self):
        # Read from your hardware or API here
        return {
            "available": True,
            "altitude": self.altitude,
            "airspeed": self.airspeed
        }
5

Test your plugin

Restart Iris. On your Phone Panel or PC overlay, configure any tile on the Generic Button Deck and select Entity → Flight Tracker → Altitude. Live values and circular gauges are available immediately!

2. Directory Structure

Iris automatically scans and loads plugins from:

  • Installed app: %USERPROFILE%\Documents\Iris\plugins\<plugin_name>\
  • Portable mode: <Iris Root>\plugins\<plugin_name>\

Every plugin requires at minimum a plugin.json manifest and a plugin.py Python script.

3. Manifest Reference (plugin.json)

The manifest tells Iris how to manage, display, and configure your plugin.

FieldTypeDescription
namestringUnique identifier. Must match the folder name (e.g. openrgb).
display_namestringHuman-readable title shown in the Iris UI.
versionstringSemantic version string (e.g. "1.0.0").
typestringLifecycle model: "app" (process-gated), "service" (always active), or "multi".
exe_defaultstringTarget process name for "app" type (e.g. "FlightSimulator.exe").
capabilitiesobjectToggles UI cards: status, configuration, buttons, outputs, live_data.
live_data.fieldsarrayList of telemetry sensor definitions exposed to the Iris Entity Bus.
buttonsarrayButton deck and status toggle definitions.
outputsarrayOutput targets (e.g. display, overlay).
settingsarrayDeclarative UI controls for the plugin's settings card.

4. Python Plugin Class Interface

Implement the Plugin class (optionally subclassing BasePlugin):

from iris_plugin import BasePlugin

class Plugin(BasePlugin):
    name = "my_plugin"

    def __init__(self, cfg=None, *args, **kwargs):
        super().__init__(cfg, *args, **kwargs)
        # Access persisted settings via self.config

    def start(self) -> None:
        """Called when enabled or when the target process starts."""
        pass

    def stop(self) -> None:
        """Called when disabled or when the target process exits."""
        pass

    def poll(self) -> dict:
        """Polled every 1.0s by Iris. Return a flat dict of live values."""
        return {"available": True}

    def on_button(self, button_id: str, slot_data: dict) -> bool:
        """Called when user taps an in-game deck button."""
        return True

    def on_action(self, action_id: str) -> bool:
        """Called when user clicks a momentary action button in settings."""
        return True

5. Lifecycle & Execution Types

Type ("type")BehaviorIdeal Use Case
"app" Focus-Gated: Automatically starts when exe_default runs, stops when the process exits. Uses 0% CPU and 0 MB RAM when game is closed. Games & Simulators (MSFS, Elite Dangerous, DCS World).
"service" Always Active: Starts on Iris boot and runs continuously while enabled. Smart home bridges, local SDK servers (OpenRGB, Home Assistant, MQTT).
"multi" Multi-Process: Starts only when all executables in requirements are active. Toolchains (RTSS + MSI Afterburner).

6. Live Telemetry & Gauges

Any key returned by poll() that matches a field defined in live_data.fields is automatically broadcast across Iris:

"live_data": {
  "fields": [
    { "key": "hull_health", "label": "Hull Integrity", "type": "percentage" }
  ]
}

When poll() returns {"hull_health": 85.5}, Iris automatically registers <plugin>.hull_health for circular gauges, button tiles, and WebSocket streaming to companion phones.

7. Buttons & In-Game Controls

Define buttons in plugin.json:

"buttons": [
  {
    "id": "landing_gear",
    "name": "Landing Gear",
    "state_key": "gear_down",
    "icon": "airplane-landing",
    "icon_off": "airplane-takeoff",
    "labels": { "on": "DOWN", "off": "UP" },
    "default_hotkey": "G"
  }
]

When tapped, Iris calls inst.on_button("landing_gear", slot_data). If on_button returns False, Iris automatically triggers the default_hotkey fallback.

8. Declarative Settings UI

Iris builds clean UI cards dynamically from your manifest — zero frontend code required:

"settings": [
  {
    "title": "Connection",
    "controls": [
      { "type": "text", "key": "api_host", "label": "Host Address", "default": "127.0.0.1" },
      { "type": "toggle", "key": "auto_connect", "label": "Auto-Connect", "default": true },
      { "type": "slider", "key": "rate", "label": "Poll Rate", "min": 1, "max": 10, "unit": "s" }
    ]
  }
]

Access values in Python via self.config.get("api_host").

9. Distribution

To share your plugin, zip the plugin folder (e.g. my_plugin.zip). Users extract it into their Documents\Iris\plugins\ directory and launch Iris!
